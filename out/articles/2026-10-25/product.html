健康相机：多模态入口是医疗 AI 的真正门槛

百度健康升级文心健康管家，发布「好医矩阵」，并推出「健康相机」——支持方言语音、拍照、边拍边说等多模态问诊入口，官方称其为全网首个健康动态视频识别能力。

关键点有两处。一是输入形态：方言语音降低了老年与下沉市场用户的使用门槛；视频/拍照则把“描述症状”这种高损耗动作，变成了“展示症状”。二是产品结构：健康管家 + 好医矩阵 + 相机，实际是把流量入口、医生供给、识别能力串成一条链路。

为什么重要：医疗是 Agent 落地中最难的一类场景，因为它要求高准确率、明确的责任主体和可追溯的流程。5000 万月活证明需求侧成立，但接下来的考验不是识别率，而是能否把识别结果接到挂号、购药、随访这些真实动作上。动态视频识别用于健康属于新尝试，其准确性与合规边界仍需观察。

GitLab 19.4：agent 开始接任务，也开始算账

GitLab 19.4 引入目标驱动的 AI 智能体，可自主拆解并推进开发任务，同时新增面向 token 消耗的成本控制能力。

值得注意的不是“agent 能写代码”，而是“目标驱动”这个措辞：输入从一条指令变成一个目标，agent 自行拆解成子任务并推进。这与传统的代码补全、单轮问答是两种产品范式。与之配套的 token 成本控制，说明 GitLab 已经预判到多步 agent 的调用量会失控。

为什么重要：企业采购 AI 开发工具时，问题正在从“效果好不好”变成“每个任务花多少钱”。把成本控制做成产品功能，而不是留给客户自己监控账单，是 agent 产品走向可运营的标志。对国内做 coding agent 的团队来说，这是一个明确的信号：能力叙事之外，必须给出单位任务的成本曲线。

讯飞：企业 agent 的 KPI 是任务闭环，不是对话轮次

科大讯飞展示其 Agent 在企业核心业务流程中的落地方式，核心主张是“Token 不空转”——以任务闭环减少无效 token 消耗，而非停留在通用问答层面。

“不空转”这个说法很产品经理：它承认了当下企业 agent 最大的浪费来源，是模型在开放式对话里反复确认、兜圈子、生成没人看的长文。讯飞的解法是把 agent 嵌进核心流程，用明确的终点（单据生成、流程推进、结果回写）来约束调用。

为什么重要：与 GitLab 同一天出现，两条消息互为印证——2026 年下半年 agent 的竞争维度已经从“能不能答”切换到“能不能交付”。对采购方而言，评估指标也应随之改变：不看 demo 里的对话质量，而看单任务的人工介入次数与 token 成本。

支付宝上车：车机是支付场景里少有的增量

支付宝车载助手亮相讯飞智能汽车发布会，双方升级战略合作并启动「讯宝计划」，车主可在车内直接办理缴费、出行等日常事务。

车机是支付的高价值场景：停车费、充电、加油、高速通行，都是“车一停就要付钱”的强需求，而手机在这一刻反而不方便。支付宝把助手放进车机，本质是把 agent 变成车内服务的统一收银台和前厅。

为什么重要：这是 agent 商业化里少见的、路径清晰的变现模型——不靠订阅，靠交易抽成。但难点也明显：车机生态碎片化，不同车厂的系统权限、语音入口、账号体系各不相同，「讯宝计划」能否跨车企复制，比首发车型更重要。

短信里的 agent：低门槛分发渠道被重新发现

TechCrunch 盘点了一批可直接在短信里运行的 AI 智能体，覆盖通用助理、家庭事务、旅行与工作等场景，认为短信正在成为 agent 的低门槛分发渠道。

优势很直接：无需安装、无需注册新账号、跨 iOS 与 Android、触达不会装 App 的人群。对旅行改签、家庭日程、外卖跟进这类短回合任务，短信的异步特性反而合适。限制同样明显：富交互能力弱，长内容与结构化选择难以承载。

为什么重要：agent 的分发一直是个未解问题——独立 App 获客贵，聊天平台受制于平台规则。短信这条“旧渠道”的价值在于它没有平台方把关。对出海和下沉市场产品，这可能是比做 App 更务实的起点。

Spotify：代码变更量翻倍，然后呢

Spotify 披露，引入 AI 辅助开发后，月度代码变更量翻倍，成为大规模团队用 AI 提升工程吞吐的代表性样本。

数字很漂亮，但要小心解读。代码变更量（code churn/change volume）衡量的是产出动作，不是交付价值。变更量翻倍可能意味着功能交付更快，也可能意味着重构、试验性提交和返工变多。

为什么重要：当 AI 把“写”的成本压下去，瓶颈会立刻转移到 review、测试和上线决策上。大规模团队真正要重设计的不是编码环节，而是评审容量与质量门禁。Spotify 这个样本的价值，在于它把问题提前暴露出来了——接下来该看的是缺陷率、回滚率和人均交付周期，而不只是变更量。
